# 任务严谨性检查清单

新建或修改任务、场景集、奖励、评分时逐条过，改完运行审计，全部 PASS 才开训或发布结果：

```
python -m aio.sim.audit                              # 仿真核心 aio/sim（docs/sim.md 第九节）
```

每条都是“问题 → 怎么查”；例子取自出过问题的装置。仿真核心里每条怎么保证，见 `docs/sim.md` 第九节。

1. **每个场景状态都物理可运行。** 不只是最终状态：每个事件之后的稳态都要检查，而且要留余量
   （四水箱：泵 0.2–9.8 V、液位 0.03–0.34 m；pH：两路流量 1–38 ml/s）。训练、验证、考试批用同一个检查
   （`aio/sim` 的 `operable`，约束工况 `point_ok`）。
2. **事后剔除不可行场景不算修好。** 生成器本身就要拒绝它们；剔除会让不同控制器的样本集不一样。
3. **约束要计分，也要在奖励里有价。** 只给跟踪计分时，牺牲约束的控制器会“赢”。
   违反量要用物理尺度归一化（例如液位 1 cm），不能用约束区间的半宽（16.5 cm 让越限几乎免费）。
   查法：算“越限 1 cm 一步的代价”和“跟踪误差一个带宽一步的代价”，前者必须更大。
   oracle MPC 的目标函数要和环境奖励一致。
4. **评分不能被执行器或基础层的速率下限主导。** 查法：同一场景集上 DMC 与 oracle MPC 的配对差中位数
   相对 oracle MPC 中位数要明显大于 0（现在要求 >10%）。如果几乎所有场景都打平，说明这组场景只测得到
   物理下限，不能用来排名。对应办法：多事件场景、必含过程变化，或者对可达参考计分。
5. **参考轨迹必须可达。** 基础层有爬坡限制（TEP 产量 30%/天）时，阶跃目标要按同样的速率发布；
   测量有窗口或滞后（TEP 牌号是最近 4 个 15 min 样本的均值）时，要和同一窗口上的目标均值比。
6. **不要在含噪测量上逐秒计窄带。** 噪声会给所有控制器加一个共同的地板。用短时均值（TEP 产量 5 min），
   或者用真值（四水箱、pH 计分用 `y_true`）。
7. **可操作性：所需执行器精度要现实。** 查法：稳态增益 × 现实执行器分辨率 ≤ 带宽。pH 无缓冲时
   dpH/dq3 可达 24 pH/(ml/s)，要 0.01 ml/s 的计量精度才能守住 ±0.2，现在限制 |dpH/dq3| ≤ 4。
8. **奖励与评分用同一参考、同一尺度方向。** 训练优化的东西要和评分一致，否则 RL 会被评分漏洞误导。
9. **训练、验证、考试批用同一个生成规则，种子不相交。** 验证批只用于选模，考试批只用于报告。
10. **参照控制器要在新场景集上重跑，并写明是哪个版本。** 旧结果文件留作历史，不和新结果混比。
