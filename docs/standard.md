# 环境标准 H4（`aio/sim/bench.py`）

环境层（Hathaway）作为基准的定版：固定考试批、参照表、统一成绩单、一致性检查。版本号 `H4`（加上 24×10、48×20 和机理装置的批）；任何会改动成绩单数字的修改都升版本，旧版本的包和参照表留着。

## 对照的现行做法

| 做法 | 出处 | 本标准 |
|---|---|---|
| 考题是随包发布的固定文件，不靠各机器现抽 | BOPTEST 测试用例、D4RL | 考试批冻结成包（`freeze` / `thaw`），任何机器逐位相同 |
| 指标由框架算，不由控制器自报 | BOPTEST KPI | `card` 在真值上算，控制器只交动作 |
| 环境带版本号，改了行为就升号 | Gymnasium `-vN`、MuJoCo/Brax | `VERSION`、批 key、参照版本写进每张成绩单 |
| 标准接口和接口自检 | Gymnasium `VectorEnv`、`check_env` | `aio/sim/gym.py`，`python -m aio.sim.bench --check` |
| 报安全指标，不只报均值 | safe-control-gym | 比不动差的占比、最差一成、物理失效数、停车数 |

## 考试批

| 批 | 内容 | key |
|---|---|---|
| `usual` | 64 台 12×5，同一台装置连住 16 段（每段 720 个决策） | `7112cb3fcc1afd29` |
| `stock` | 64 台，每台带守恒的库存链，8 段 | `1cd585e1035b3d0c` |
| `standard` | 标准生成器：`usual` 加四分之一装置带库存链，64 台 16 段 | `88c268fc117a0251` |
| `usual24` | 64 台 24×10，工业 APC 的形态，8 段（参照取 11-13 定版的那份：只有次数分） | `a03cef5e7bad038b` |

|---|---|---|
| `usual48` | 32 台 48×20，8 段；包 73 MB 不进仓库，放在 `$AIO_BENCH_DATA`（共享盘 `sim/bench/H4/`） | `1ffb5fec1947bbad` |
| `mech`、`mech_new` | 机理装置（先十种、后五种），64 台 8 段 | `0d2615745b137a1d`、`05f96345d9da52da` |

这三批在 Colab G4 上算（11-16，`--make 名 --device cuda --dir 目录`）。**机理批还不是跨机器一致的**：机理引擎冻结不了，只能从种子建，而同一种子在别的机器建出的是另一批（云端 CPU 是 `0d0a787c42472d2c`，建一次 50 分钟）；这两批的成绩单只在建得出该 key 的机器（Colab G4）上读，key 不对直接报错。下一步是把机理批也冻结成包。默认成绩单只读包在仓库里的四批。

**标准生成器** `prior.STANDARD`（`shape=dict(stock=.25)`）：四分之一的装置带守恒的库存链。正式训练用 `--menu stock=0.25`；`build()` 不给 `shape` 仍是原生成器，旧批逐位不变。

## 接口

- 观测：数据包（`aio/interface.py`），全部无量纲；只由仪表读数、目标、限值和已发指令组成。
- 动作：每个 MV 一个数，[-1, 1] 倍速率限；超出的按限值算。
- 控制器：`reset(prog)`、`__call__(prog, st, k, obs)`，只许读 `obs`。`--ctl 模块:工厂` 接入（`aio/sim/plugin.py`）。
- Gymnasium：`aio.sim.gym.VecEnv(num_envs, seed, device, reward='outside'|'cost'|'soft', tensors, grad)`。

## 成绩单

`python -m aio.sim.bench --ctl 模块:工厂 --arg 权重 --out card.json`。控制器在装置上自己住满全部段；每台装置的带外决策数逐段相加。

| 字段 | 含义 |
|---|---|
| `points` | 0 是 MV 不动，100 是每台装置上最好的参照；按带外的行·决策数（出带多久） |
| `cost_points`、`cost_worse` | 同一把尺按代价算（偏多远：带宽为单位的误差平方，越限 ×10）；按代价比不动差的装置占比 |
| `worse` | 比不动差的装置占比 |
| `low`、`worst` | 最差一成装置上的分数、最差一台的分数 |
| `outside` | 带外的行·决策占比 |
| `failed`、`tripped` | 物理失效、越过停车限的装置·段数 |

分全部、带液位、其余三栏；附 `bench`、`key`、参照版本、torch 版本和提交号。

**两个分都报**：次数分只数出带多久，代价分看偏多远，两者会不一致。`stock` 上老师按次数在 7 台输给自整定PID 5% 以上，按代价只有 1 台（只看仪表的 2 台）：它不让下游区间行短暂大幅越限，缓冲罐液位因此久在带外。老师门槛按代价分判。

## 一致性检查

`python -m aio.sim.bench --check`：包就是该批；同一回放两次逐位相同；数据包之外的状态全部打乱，数据包不变（无特权信息）；超限动作等于限值动作；数据包有限；库存链上一股流从一个罐减多少、往下一个罐加多少。

## 失效范围

没有。默认生成器、现有考试批、参照和 key 都不变；`stay.references` 只多报一项 `tripped`。
